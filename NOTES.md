# NOTES: the specifications this package was built against

Read on 29-30 Oct 2026 (UTC). Each item names what was relied on; anything not run is marked UNTESTED.

- **Agent Skills specification**, https://agentskills.io/specification. SKILL.md with YAML frontmatter. Required: `name` (1-64 characters, lowercase letters, digits and single hyphens, no leading or trailing hyphen, must match the parent directory) and `description` (1-1024, says what the skill does and when to use it). Optional: `license`, `compatibility` (max 500), `metadata` (a map of string keys to string values, "clients can use this to store additional properties"), `allowed-tools` (experimental). Keep SKILL.md under 500 lines; references one level deep. Validator named: `skills-ref validate` (https://github.com/agentskills/agentskills/tree/main/skills-ref), **UNTESTED** (not installed: running a downloaded package was not done; `scripts/validate.mjs` re-implements the documented rules, with negative controls).
- **skills.sh and its CLI**, https://skills.sh and https://github.com/vercel-labs/skills (README and docs/creating-skills.md). `npx skills add <owner/repo> [--skill <name>] [-a <agent>]`. Discovery in a repository: the root if it has SKILL.md, `skills/`, `skills/.curated/` and others, and the skills declared in `.claude-plugin/marketplace.json` or `plugin.json`. Required frontmatter `name` and `description`. The site shows a leaderboard by install counts; the pages read do not describe a submission step, and the README says the CLI collects anonymous usage data (`DISABLE_TELEMETRY=1` turns it off). How a repository appears on the site is **not documented in what was read**: UNKNOWN. `npx skills add` was NOT run (it would download and run code).
- **Claude Code plugin marketplaces**, https://code.claude.com/docs/en/plugin-marketplaces and the manifest reference https://code.claude.com/docs/en/plugins/manifest-reference. `.claude-plugin/marketplace.json` requires `name`, `owner` and `plugins[]`; each entry needs `name` and `source` (a relative path from the marketplace root, `"./"` for a plugin at the root). `.claude-plugin/plugin.json`: `name` is the only required key (kebab-case; names starting `claude-`, `anthropic-` and a few others are reserved); skills live in `skills/<name>/SKILL.md` by default. The entry name must equal the manifest name. Add with `claude plugin marketplace add <owner/repo>`, install with `claude plugin install <plugin>@<marketplace>`. **Validated here with `claude plugin validate` (Claude Code 2.1.266): passed.** The add and install commands were NOT run (they change the user's settings).
- **ClawHub**, https://docs.openclaw.ai/clawhub/skill-format. Required file SKILL.md; optional frontmatter `name`, `description`, `version`, and `metadata.openclaw` with `requires.env`, `requires.bins`, `primaryEnv`, `envVars[]` (name, required, description) and `homepage`. Every published skill is licensed MIT-0 and a conflicting license in SKILL.md is not allowed; paid skills and pricing metadata are not supported (this skill puts no price in its frontmatter; its body states the prices of the API it calls, from the generated facts: UNKNOWN whether ClawHub moderation accepts that, flagged for the owner). The page read does not state the publish command; a search result for the quickstart gives `clawhub skill publish ./my-skill` (npm package `clawhub`): UNVERIFIED, and the publish was NOT run.
- **Hermes Agent**, https://hermes-agent.nousresearch.com/docs/user-guide/features/skills. SKILL.md with `name`, `description`, `version`, `platforms`, `metadata.hermes` (tags, category, requires_toolsets, config) and a top-level `required_environment_variables` block (name, prompt, help, required_for). Skills live in `~/.hermes/skills/`; install `hermes skills install owner/repo/skills/<name>` or from a URL. Cron jobs never prompt and never auto-trust; when a skill's secrets are missing, non-interactive surfaces direct the user to `hermes setup` or `~/.hermes/.env`. This package does NOT use the top-level `required_environment_variables` block (it is not in the Agent Skills specification, and a strict validator may reject an unknown top-level field), so Hermes will not prompt for `AGENTFEED_KEY`; SKILL.md and references/SCHEDULING.md tell the user to put it in `~/.hermes/.env`. A Hermes install was NOT run.
- **Nested metadata:** the Agent Skills specification describes `metadata` as string keys to string values; ClawHub and Hermes read nested maps (`metadata.openclaw`, `metadata.hermes`). The skill has them. A validator that enforces string-only values would reject the file: **UNTESTED** (`skills-ref` not run). If that happens, the fix is to drop the two nested blocks and lose ClawHub's env declaration and Hermes' tags.
